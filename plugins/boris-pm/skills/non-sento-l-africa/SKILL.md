# Non sento l'Africa — la prova del perché

> **La scena.** Stanis La Rochelle, il divo della fiction, si lamenta di "non sentire l'Africa": la scena c'è, ma manca l'anima, l'essenza autentica.
> **Sul tuo set.** Progetti, funzionalità, eventi e documenti possono avere tutto tranne un motivo per esistere. Questa skill cerca l'Africa: se c'è la mette per iscritto, se non c'è lo dice.

## Cosa ti serve

L'oggetto da esaminare (idea, progetto, funzionalità, evento, documento, richiesta di un capo o di un cliente) e quello che l'utente sa su utenti, dati e contesto. Se esiste `boris/progetto.md`, leggilo.

## Come lavori

1. **Riscrivi l'oggetto in una riga** neutra: cosa si vuole fare.
2. **Scava con i perché.** Chiedi "perché?" fino a cinque volte, con quello che sai o chiedendo all'utente, finché non arrivi a un cambiamento nella vita o nel lavoro di qualcuno, non a un'attività. "Facciamo l'app" → perché? → "i soci non sanno quando ci sono gli eventi" → perché? → …
3. **Compila la prova dell'Africa**: sei domande, ognuna con la risposta e il livello di prova.

   | Domanda | Risposta | Lo sappiamo o lo pensiamo? |
   |---|---|---|
   | Quale problema o opportunità? | | |
   | Per chi, esattamente? (un gruppo che si può trovare e contattare) | | |
   | Come lo risolvono oggi, e cosa non funziona? | | |
   | Cosa cambia per loro se lo facciamo? (il risultato, non il prodotto) | | |
   | Come misuriamo che ha funzionato? (metrica, valore, data) | | |
   | Perché adesso, e cosa succede se non lo facciamo? | | |

   "Lo sappiamo" vuol dire che c'è una prova: dati, parole di utenti veri, ordini, iscrizioni, richieste ripetute. Tutto il resto è "lo pensiamo", e va bene, purché sia scritto.
4. **Distingui il prodotto dal risultato.** Se il successo è "abbiamo fatto la cosa" (il sito è online, l'evento c'è stato), riformulalo come cambiamento: "+30% di iscrizioni dal sito entro giugno".
5. **Trova la prova più economica** per le due ipotesi più rischiose: cinque telefonate a utenti veri, i dati che ci sono già, una pagina di prova, un'anteprima per pochi, la richiesta di un impegno (iscrizione, preordine, firma). Scegli quella che risponde in giorni, non in mesi.
6. **Il verdetto.**
   - **Sento l'Africa** — il perché è chiaro e c'è almeno una prova: si va.
   - **La sento poco** — il perché regge ma poggia su ipotesi: si va dopo la prova indicata, oppure in piccolo.
   - **Non la sento** — nessuno ha davvero bisogno di questa cosa, o non si sa chi: fermarsi o ripensare. Dillo chiaramente: risparmiare mesi di lavoro inutile è il servizio più prezioso che puoi rendere.

## Cosa consegni

```
**L'Africa in una frase:** Per <chi>, che oggi <problema>, <cosa facciamo> permette di <risultato>; lo misureremo con <metrica> entro <data>.
**Verdetto:** Sento l'Africa / La sento poco / Non la sento — <perché, in due righe>
**Prova dell'Africa:** <la tabella>
**Ipotesi da verificare:** 1. … → prova: … (costo, tempo)
**Cosa cambierei:** <nel progetto o nel documento, se serve>
```

Se esiste `boris/progetto.md`, proponi di aggiornare la sezione "Perché" con la frase e la metrica.

## Errori da evitare

- Accettare "tutti" come risposta a "per chi".
- Scambiare l'entusiasmo della squadra per una prova.
- Metriche di vanità (visualizzazioni, like) quando il risultato vero è un altro (iscrizioni, vendite, persone formate).
- Essere gentili con un'idea che non sta in piedi: dirlo presto è un favore.

## Tono

Una battuta in apertura o in chiusura, poi lavoro serio. I testi per altri escono puliti. Niente prove inventate: se non lo sai, è "lo pensiamo". Rispondi nella lingua dell'utente.
